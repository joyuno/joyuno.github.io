오늘 손댄 건 네 군데였다. 사주 궁합 사이트에서 공유 문구가 사라지던 문제와 카카오 공유 보상이 브라우저 보안 정책에 막히던 문제, 그리고 마케팅 자동화에서 같은 뉴스로 영상과 캐러셀이 겹쳐 나오던 문제와 컷마다 얼굴이 바뀌던 문제다. 앞의 둘은 증상이 명확했고, 뒤의 둘은 코드를 열어 봐야 원인이 보였다.

## 오연 — 공유하면 문구가 사라지고 링크만 복사되던 문제

결과 화면에서 "친구에게 이 결과 보내기"를 누르면 공유창 대신 클립보드에 주소만 들어갔다. 문구는 어디로도 가지 않았다.

로컬에서 브라우저로 흐름을 그대로 돌렸는데 `#share:not([hidden])` 셀렉터가 20초, 다시 30초에서 타임아웃했다. 로그에는 `43 × locator resolved to hidden <button id="share" type="button" class="secondary">`가 찍혔다. 버튼은 DOM에 있는데 hidden이었다.

처음엔 공유 코드 쪽 문제라고 봤다. 그런데 버튼이 숨어 있는 게 먼저 걸렸다. 상태를 직접 찍어 보니 `{"err":"","results":true,"hash":"#top","app":true,"ranks":0,"shareParentHidden":"results"}` — `#results`가 hidden이었다. 폼 검증은 통과하고 있었다(`{"bad":[],"msg":""}`). 범인은 "출생 시간을 모른다" 확인 다이얼로그였다. `모른 채로 보기`를 눌러야 결과 화면이 열리는데, 그걸 누르지 않은 채 공유 버튼만 기다리고 있었던 것이다.

> 버튼이 안 눌린 게 아니라, 버튼이 들어 있는 화면이 아직 열리지 않았었다.

그다음 진짜 공유 문제. 링크만 복사된 이유가 이거였다.

**해결**은 문구와 주소를 한 칸에 합쳐 `text`로 넘기는 것. `navigator.share`가 없는 브라우저에서는 합친 문자열을 그대로 클립보드에 쓴다. **검증**은 `navigator.share`를 `undefined`로 만든 뒤 버튼을 눌러 클립보드를 읽는 방식으로 했다. `"내 100점 궁합 1위는 2002년 11월 20일생이래. 이 날 태어난 사람 알아? 네 100점 궁합도 찾아 봐."` 뒤에 주소가 한 문자열로 붙어 나왔고, 버튼 문구도 "보낼 문구와 주소를 복사했어요"로 바뀌었다. 공유창 경로는 `window.__shared`를 가로채 넘어간 값을 확인했다.

결제한 결과의 링크 공유는 이용권이 있어야 해서 직접 돌려보지 못했다. 이건 아직 남아 있다.

## 오연 — 카카오 공유 보상이 CSP에 막혀 창이 안 열린 문제

결과 화면에 노란 버튼을 붙였는데, 눌러도 공유창이 안 뜨고 "이 기기나 같은 인터넷 연결에서 이미 1회권을 받았어요"만 떴다.

위젯 자체가 없었다. 앞 섹션과 같은 함정이었다 — 결과 화면까지 가지 않았으니 위젯이 그려질 리 없었다.

그때 콘솔에 에러가 찍혀 있었다.

> `Sending form data to 'https://sharer.kakao.com/picker/link' violates the following Content Security Policy directive: "form-action 'none'"`

**첫 가설**은 CSP `form-action`에 `sharer.kakao.com`을 넣으면 된다는 것. 넣고 다시 돌렸더니 메시지가 바뀌었다. `violates ... "form-action https://sharer.kakao.com"`. 여전히 차단이다. 지시문에 넣은 값과 폼이 실제로 향하는 곳이 다르다는 뜻이었다. 공유창이 열린 뒤의 팝업 주소를 보니 `https://accounts.kakao.com/login/?continue=https%3A%2F%2Fsharer.kakao.com%2Fpicker%2Flink%3Fapp_key%3D...` — 리다이렉트 끝에 로그인 호스트가 있었다. 그 호스트까지 허용하고 나서야 창이 열렸다.

이어서 1회권 중복 방어를 붙였다. 로컬 e2e에서 `AssertionError: 같은 기기 번호라도 브라우저가 다르면 못 받음 / actual: undefined, expected: 'unknown'`이 났다. 서버가 브라우저 특징값 없는 요청에 `'unknown'`을 돌려줄 거라 가정했는데 응답에 그 필드가 없었다. 응답 형식을 맞추고 층을 쌓았다.

| 막는 기준 | 한도 |
|---|---|
| 기기 번호 / 브라우저 특징값+인터넷 대역 | 평생 1장 |
| 같은 IP | 7일 1장, 30일 2장 |
| 같은 인터넷 대역 | 30일 4장 |
| 카카오 채팅방 | 방 하나 1번, 나와의 채팅 0장 |
| 사이트 전체 | 하루 50장 |

**검증**은 로컬 시나리오 13개, 운영에서 브라우저 특징값 없이 오는 요청이 거절되는 것까지 확인했다. 실제 카카오 전송은 휴대폰 로그인 추가 인증이 필요해서 아직 못 봤다. 서버에 '나와의 채팅'으로 기록되는지가 마지막 확인으로 남아 있다.

## 라피드 — 같은 뉴스로 영상과 캐러셀이 겹쳐 나온 문제

11-24 20:00 영상(#16)과 21:00 캐러셀(#17)이 같은 '오분만' 알람 앱 뉴스를 소재로 썼다. 겹침 검사가 있으니 걸렀을 거라 생각하고 코드를 열었는데, 검사는 제목 낱말만 비교하고 있었다. 두 기획은 23일과 24일에 따로 만들어져 제목이 달라 통과한 것이다.

**원인**은 같은 원본 뉴스, 같은 제품을 봐도 제목이 다르면 다른 이야기로 취급된다는 것. **해결**은 최근 48시간 안에 쓴 글과 원본 뉴스가 같거나 같은 제품을 다루면 같은 이야기로 보고 건너뛰게 하는 것이다.

부수 문제도 나왔다. 캐러셀에도 영상용 "(가상 상황극) 하루가…" 줄거리가 근거 자료로 넘어가고 있었다. 캐러셀은 정보·비교·테스트용인데 출연진 상황극이 붙은 것. 캐러셀에는 사실과 원본 뉴스만 넘기고, 작성 규칙에 "주인공은 독자, 출연진·상황극 금지"를 넣었다.

**검증**은 같은 시각으로 다시 만드는 것. 글 번호가 #17·#18에서 #21·#22로 바뀌었다. #21은 출연진 없이 4장으로 나왔지만 원본이 블로그 글 하나라 실제 문항이 없어 "테스트"라는 표지가 약속을 못 지킨다 — 버리는 게 낫다고 판단했다. #22는 6장짜리 정보 캐러셀로 나왔다. 다만 표지와 첫 장 그림이 NVIDIA 이미지 필터에 `CONTENT_FILTERED`로 막혀서, 'MacBook'을 일반 노트북으로 묘사를 바꿔 무료로 다시 그렸다. #22의 분야 꼬리표가 "테스트"로 잘못 붙은 건 아직 남아 있다.

## 라피드 — 컷마다 얼굴이 바뀐 문제, 원인은 미리보기 구조였다

A 영상 4컷에서 하루가 컷마다 다른 사람이었고, 서양인 얼굴이 섞이기도 했다. 처음엔 프롬프트에서 외형 설명이 약한 줄 알고 확인했더니, 외형 문장이 장면 묘사 뒤 800~1,200자 지점에 묻혀 있었다.

**시행착오** 셋을 돌렸다.

- 외형을 맨 앞으로 → 얼굴은 고정되는데 장면이 사라지고, 두 사람이 나오는 컷에서 한 명으로 합쳐졌다.
- 첫 문장 바로 뒤로 → 얼굴은 고정, 장면은 약해지고 강민이 빠졌다.
- 장면 묘사를 짧게 줄여 외형 비중을 높임 → `CONTENT_FILTERED`가 3건, 결과도 들쭉날쭉했다.

> 무료 이미지 모델은 참조 사진을 받지 못한다. 글로만 그리니 얼굴 고정과 장면 유지가 서로 자리를 뺏는다.

그때 진짜 문제가 보였다. 미리보기는 무료 모델로 그리는데, 유료 제작 때도 그 무료 이미지를 그대로 다시 쓰는 구조였다. 미리보기 얼굴이 깨지면 최종 영상도 깨진다는 뜻이다. **해결**은 출연진이 나오는 컷은 제작할 때 기준 사진을 참조해 다시 그리고, 편집 화면에서 직접 고른 이미지는 그대로 두는 것. 테스트 329개가 통과했다.

미리보기 자체는 여전히 얼굴이 흔들린다. 미리보기부터 유료로 참조 사진을 넣으면 영상 1편에 약 $0.3~0.4, 하루 4편이면 월 $40으로 지금 영상 예산과 맞먹는다. 그래서 미리보기는 무료로 두고 제작 단계에서 바로잡는 쪽으로 결정했다.
