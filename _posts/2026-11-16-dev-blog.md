오늘은 lepons 릴리스 마무리와 폰 앱 재제출을 한 번에 돌렸다. macOS dmg 서명이 SSH 세션에서 막혔고, 사용량 집계가 이상한 폴더로 쪼개져 있었고, iPhone에서 md 파일 일부만 골라 복사가 안 됐다. 세 가지 다 원인을 짚어서 고친 뒤 빌드까지 돌렸다.

## lepons macOS 빌드 — SSH 세션의 잠긴 키체인이 codesign을 막았다

`npm run dist:mac`을 돌렸는데 서명 단계에서 `errSecInternalComponent`로 실패했다. 이 오류는 codesign이 키체인의 서명 키를 쓰지 못할 때 나온다. 빌드 로그보다 먼저 맥에 들어와 있는 세션을 확인했더니 전부 이 PC에서 연결한 SSH였다. Lepons 창 안에서 실행하면 SSH라 로그인 키체인이 잠긴 상태가 된다.

**첫 가설**은 키체인 잠금이었고, 그대로 맞았다. 다만 여기서 두 갈래로 나눠서 판단했다.

- **이미 있던 dmg 재사용**: 11/13 15:50에 만든 1.10.6 dmg가 `release/`에 남아 있었고 `stapler validate`도 통과한 상태였다. 커밋 0696462(11/13 14:40) 다음은 786564f(11/14) 하나뿐인데 `mobile/src` 파일 4개만 바꿨고 `cockpit/`, `relay/`, `site/`는 손대지 않았다. PC 빌드 스크립트(`build.mjs`, `package.json`)는 `mobile/`을 읽지 않으니 그 dmg는 지금 1.10.6과 같은 코드다.
- **새로 빌드**: 맥의 터미널 앱에서 직접 `security unlock-keychain ~/Library/Keychains/login.keychain-db`로 잠금을 풀고 다시 돌린다.

> SSH 세션에서 띄운 Lepons 창은 키체인이 잠겨 있어 codesign이 서명 키를 못 쓴다.

업로드에서 한 번 더 막혔다. 맥의 `gh`가 SSH 세션이라 GitHub 인증을 못 읽어서 401이 났다. 이 PC에서 `scp`로 dmg를 받아 대신 올리기로 했다. 처음엔 `scp`가 `No such file or directory`로 실패했는데, 원격 경로의 `~`가 셸에서 확장되지 않고 그대로 넘어간 문제였다. 원격 절대 경로로 바꾸니 받아졌다.

**검증**은 체크섬으로 했다. 받은 파일과 맥 원본의 SHA-256이 같은 것을 확인하고 `gh release upload v1.10.6`로 올렸다. 파일명은 `Lepons.Cockpit-1.10.6-arm64.dmg`로, 1.10.4와 같은 이름이라 lepons.app의 macOS 다운로드 버튼이 그대로 찾는다.

## lepons 사용량 집계 — 서브에이전트와 워크트리가 별도 프로젝트로 잡혔다

사용량 화면에 `.work` ($1.50), `1` ($0.61) 같은 이상한 묶음이 프로젝트로 잡혀 있었다. 원래 규칙도 "세션을 시작한 폴더 기준 → 등록 폴더 또는 git 저장소"였으니 계산식 자체는 맞는 것처럼 보였다. 그런데 이 PC 기록을 실제로 돌려 보니 두 군데서 어긋났다.

- `.work` ($1.50): trend-posts 세션의 **서브에이전트 기록**이 따로 저장되는데, 이걸 별개 대화로 보고 서브에이전트가 일한 폴더 `trend-posts/.work`를 기준으로 셌다. 그 폴더가 자체 git 저장소라 따로 묶였다.
- 워크트리 폴더를 별도 저장소로 본 결과다.

> 워크트리와 서브에이전트 기록까지 각자 저장소로 세고 있었다.

**해법**은 `cockpit/src/agent/token-stats.ts`의 묶는 기준을 두 줄로 좁히는 것이었다. Claude Code는 세션을 시작한 메인 경로로 세고, 서브에이전트 기록은 자기를 실행한 세션의 메인 경로로 들어가게 했다. git 워크트리는 원래 프로젝트로 센다. 다른 워크트리도 마찬가지다.

**검증**은 사용량 테스트 15개와 타입 검사 통과로 확인했다. 새 테스트는 서브에이전트, 워크트리, Codex 워크트리 세 경우를 잡는다. 사용량 기록 파일(`~/.claude/projects/…`, `~/.codex/sessions/…`)은 PC 앱만 읽을 수 있어서 이 계산이 PC에서 이뤄지고, 폰은 결과만 그린다. 그래서 PC 앱 업데이트가 나가야 화면이 바뀐다.

이 수정을 담아 1.10.7을 Windows용으로 냈다. 앱 코드만 바뀌어서 Windows는 앱 안 '업데이트'로 작은 패치(`asar.gz`)로 갱신된다. PC 테스트는 실패 0으로 통과했고, 패치 안에 새 사용량 코드가 들어간 것도 확인했다.

## lepons md 뷰어 — 문단마다 쪼갠 Text가 부분 선택을 막았다

iPhone에서 md 파일 일부만 골라 복사가 안 됐다. md 뷰어는 문단마다 일반 글자 칸을 따로 썼는데, iPhone에서는 이런 칸을 선택하면 **문단 전체 복사**만 되고 범위를 못 잡는다. 채팅 화면은 이 문제를 이미 피해 갔는데(`SelectableText`), md 뷰어에는 그 방식이 안 들어가 있었다.

**해법**은 `mobile/src/app/doc.tsx`에서 이어지는 문단·제목·목록·인용을 채팅처럼 한 덩어리 글로 묶는 것이었다. 원하는 부분만 끌어서 복사할 수 있고, 문단을 넘어서도 선택된다. 코드 블록도 부분 선택이 되게 바꿨다. 표는 칸마다 통째로 복사되는데, 채팅 화면의 표와 같은 방식이다.

같이 점검한 곳도 셋 있었다. 코드 파일 보기(줄마다 따로라 한 줄 전체만 복사), 지도 → 작업 요약 시트(선택 자체가 안 됨), '입력 대기' 미리보기(전체만 복사). 셋 다 고쳤다. 코드 파일 보기에는 위쪽에 '선택' 버튼을 넣어 파일 전체를 한 덩어리 글로 보여 준다. 10만 자가 넘는 파일에서는 버튼이 안 나오고 '복사'로 전체를 복사한다.

**검증**은 타입 검사와 테스트 147개 통과, 별도 리뷰에서 버그 없음까지 확인했다. 다만 실제 iPhone에서는 아직 확인하지 못했다. 빌드 34와 Android 19로 다시 올렸고, App Store는 33 심사를 빼고 34로 재제출해서 지금 '심사 대기 중'이다.

## automation — 계정 상태 확인에서 게시 중단을 결정했다

이건 에러가 아니라 상태였다. 실행 직후 Aside 브라우저 로그인 상태를 확인했더니 두 가지가 어긋나 있었다.

- **Threads**: @aiproduck 프로필 사이드바에 '로그인'과 '팔로우' 버튼이 보이고 글 작성 칸이 없었다. 11-11부터 4회 연속 같은 상태.
- **X**: @aiproduck이 아니라 @rafeed_ai로 로그인.

**판단**은 소스 수집·초안 작성·예약을 하지 않고 중단하는 것이었다. 대신 `logs/2026-11-16.md`에 중단 사유와 필요한 조치를 적고, `state.json`에 이번 실행 기록만 추가했다(`posted`, `scheduledDates`는 그대로). `MEMORY.md`에 연속 중단 기록을 11-16까지로 갱신했다.

**남은 과제**는 Aside 브라우저에서 Threads에 @aiproduck으로 다시 로그인하고, X 계정을 @aiproduck으로 전환하는 것이다. 그 전까지는 매 실행이 같은 이유로 중단된다.
