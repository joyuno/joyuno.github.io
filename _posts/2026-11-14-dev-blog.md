오늘은 세션 탭의 워크트리 표시를 갈아엎고, 그걸 빌드 33으로 올려 TestFlight까지 넘기는 하루였다. 화면 한 곳을 고치는 일이었는데 정작 그 화면은 끝까지 눈으로 못 봤고, 중간에 파일 치환 스크립트가 두 번 깨졌다. 무엇을 고쳤는지보다 **무엇을 확인했고 무엇을 못 했는지**를 갈라 두는 데 시간이 더 들어간 날이었다.

## 세션 탭 워크트리 표시 — 들여쓰기를 걷어내고 C-2로 간 이유

지금 화면은 원본 프로젝트 줄 아래에 워크트리가 붙는 구조인데, 한 카드 안에서 줄마다 가로 구분선이 끝까지 그어져 있었다. 그래서 들여쓰기한 트리 세로선과 구분선이 서로 엇갈려 보였고, 워크트리 줄에 원본 이름 `lepons`가 한 번 더 찍혔다. 계층을 들여쓰기와 세로선으로 그리는 방식 자체가 카드형 행과 안 맞는다고 봤다.

처음엔 계층 표현을 네 갈래로 놓고 비교했다.

| 시안 | 방식 | 걸리는 점 |
|---|---|---|
| A | 트리 선만 제거, 들여쓰기 유지 | 고칠 양은 가장 적지만 계층 표현 방식은 그대로 |
| B | 원본 폴더 하나 = 카드 하나 | 선·들여쓰기 전부 사라짐. 대신 카드 수가 그대로 늘어 목록이 길어짐 |
| C | 원본 줄을 눌러 접고 펼치기 | 워크트리 상태를 보려면 한 번 더 눌러야 함 |
| D | `lepons ⑂ rail-anchor` 한 줄 경로 | 가장 단순하지만 관계가 이름으로만 보임 |

B를 먼저 추천했다. 문제를 근본적으로 없애는 쪽이었기 때문이다. 그런데 워크트리가 세 개만 붙어도 카드가 네 장이 되니 목록 길이가 바로 문제가 됐다. 결국 접고 펼치는 C로 방향을 틀었고, C 안에서 펼친 모양을 다시 세 개로 쪼갰다. 칩을 가로로 흘리는 C-1, 옅은 패널에 담는 C-2, 작은 카드가 안쪽에 매달리는 C-3이었다.

> C-1은 칩 폭이 좁아 진행 문구가 잘렸고, C-2는 구분선을 없애면서 지금 화면에서 달라지는 폭이 가장 작았다.

최종적으로 C-2를 골랐다. 표 격자 느낌을 가장 많이 걷어낸 건 C-3 쪽이었지만, 이번 빌드에서는 변경 폭을 줄이는 쪽을 택했다.

바뀐 동작은 이렇게 정리된다.

- 워크트리가 있는 원본 줄은 처음에 접힌 상태로 시작하고, 이름 옆 `⑂ 3 ●●○`에 개수와 상태 점이 보인다.
- 원본 줄을 처음 누르면 펼쳐지고 오른쪽에 `›`가 생긴다. 한 번 더 누르면 그 프로젝트 채팅으로 간다.
- 워크트리 줄은 누르면 바로 그 워크트리 채팅으로 간다. 맨 오른쪽 `⌃`/`⌄`로 언제든 접고 펼친다.
- 워크트리가 없는 줄은 예전처럼 한 번 누르면 채팅이다.

수정한 파일은 네 개다. `mobile/src/app/(tabs)/sessions.tsx`, `ui.tsx`, `swipe-row.tsx`, `i18n.ts`. 다크 모드 색도 따로 잡았고, 패널 안의 세션도 왼쪽으로 밀어 닫기·다시 연결이 되도록 `SwipeRow` 표면을 손봤다. 예전 트리 선과 워크트리 줄의 원본 이름 중복은 없앴다.

**검증**은 타입 검사와 기존 테스트 147개 통과까지였다. 별도 리뷰에서 확실한 버그는 안 나왔고, 확신도가 낮은 지적 두 개는 바로 반영했다. 화면 낭독기가 "누르면 워크트리가 펼쳐진다"를 읽어 주도록 안내를 붙였고, 닫힌 폴더를 열어도 펼쳐 둔 상태가 접히지 않게 고쳤다.

## 웹 미리보기 빈 화면 — 500 뒤에 있던 `@xterm/headless`

UI를 바꿨으니 눈으로 확인하려고 웹으로 띄웠는데 화면이 비어 있었다. 콘솔에는 오류 두 개가 찍혀 있었다.

- `Failed to load resource: the server responded with a status of 500` — `node_modules/expo-router/entry.bundle` 요청
- `Refused to execute script ... because its MIME type ('application/json') is not executable`

처음엔 번들이 아직 안 만들어졌고 500 응답이 JSON 에러 바디로 온 거라고 봤다. 그래서 Metro 로그를 열었더니 원인이 바로 나왔다.

> `Unable to resolve "@xterm/headless" from "src\app\session\[id].tsx"` — Web Bundling failed 2993ms (1168 modules)

네이티브 빌드는 통과했으니 웹 번들 경로에서만 resolve가 실패한 셈이다. 여기서 한 번 캐시를 의심했다. Metro가 CI 모드로 떠서 reloads are disabled 상태였기 때문에 이전 결과를 그대로 물고 있을 수 있었다.

캐시를 비우고 다시 띄웠더니 이번엔 다른 에러가 나왔다. `Port 8099 is unavailable and 'npx expo' is running in non-interactive mode` — 아까 띄운 Metro가 아직 8099를 잡고 있었다. 해당 프로세스를 정리하고 재시작하니 번들이 정상적으로 올라왔고, 화면이 떴다.

다만 거기서 끝이 아니었다. 첫 화면에 `ExpoSecureStore.default.getValueWithKeyA` 오류 창이 떴다. 웹에는 보안 저장소가 없으니 예상된 실패라 닫고 넘어갔다. 문제는 그다음이었다. 데모 모드 목록에는 펼칠 워크트리가 없었다. 워크트리의 원본이 '입력 대기' 카드로 맨 위에 올라가면서, 정작 확인하려던 펼침 패널이 화면에 나오지 않는 상태였다.

**결론적으로 C-2 패널은 이번에도 눈으로 못 봤다.** 웹 미리보기로 확인한 건 "앱이 뜬다"까지였고, 바뀐 화면은 빌드 33의 TestFlight에서 처음 보게 된다. 데모 데이터를 임시로 손대는 방법도 있었지만 그건 되돌리고, 대신 바뀐 코드를 독립 리뷰에 다시 물렸다.

## 일괄 치환 스크립트 — heredoc이 백틱에 걸리고, assert가 두 번째를 잡았다

파일 네 개를 고치는 과정에서 문자열 치환을 파이썬으로 돌렸다. 첫 시도는 `python - <<'EOF'`로 스크립트를 넘겼는데 `Exit code 2`와 함께 `unexpected EOF while looking for matching '`가 떴다. 원인은 치환 대상 코드 안에 들어 있던 백틱이었다. heredoc 안이라도 셸이 백틱을 먼저 해석해 버려서, 파이썬이 받은 스크립트가 중간에서 끊긴 거였다.

> 셸이 백틱을 먼저 먹었고, 파이썬은 잘린 스크립트를 받았다.

스크립트를 `.py` 파일로 옮기니 이 문제는 사라졌다. 문제는 그다음이었다. 리뷰 지적을 반영하려고 치환을 한 번 더 돌렸는데 이번엔 파이썬이 죽었다.

```
AssertionError: ('toggle(item.key)', 2)
```

치환 헬퍼에 `assert s.count(a) == 1`을 걸어 뒀는데, 바꾸려던 `toggle(item.key)`가 파일 안에 두 군데 있었다. 처음엔 귀찮은 실패라고 생각했지만 곧 생각이 바뀌었다. assert가 없었으면 같은 문자열 두 곳을 조용히 다 바꿔 놓고, 의도하지 않은 자리까지 건드린 걸 나중에나 알았을 테다.

그래서 헬퍼를 `rep(a, b, n=1)` 형태로 고쳐 개수를 인자로 받게 하고, 두 군데를 바꿔야 하는 자리는 개수를 명시해서 호출했다. 이후 타입 검사와 테스트 147개를 다시 통과했고, 그 상태로 맥에 바뀐 파일 네 개를 넘겨 iOS 빌드를 걸었다.

## 마무리
