오늘은 모바일 로그인 만료 처리, 폰에서 꺼둔 PC를 켜는 문제, 그리고 worktree 기능 설계와 구현 중에 나온 버그 세 건을 잡았다. 로그인은 화면 스택이, PC 연결은 버튼 노출 조건이, worktree는 실패를 성공으로 흘려보내는 코드가 원인이었다.

## 모바일 로그인 만료 — 쌓인 화면이 남아 뒤로가기가 필요했던 문제

증상은 이랬다. 로그인이 끝나면 탭 화면만 첫 화면으로 돌아갔다. 그 위에 열어 둔 세션·설정·문서 화면은 그대로 남아 있어서, 뒤로가기를 눌러야 이동이 일어났다. 시간이 지나 세션이 만료된 경우도, PC에서 끊은 경우도, 직접 로그아웃한 경우도 같았다.

먼저 `app/index.tsx`와 `connection.tsx`를 봤다. `signedOutHere`가 토큰과 폰 상태를 지우고, `emit`에서 `end` 이벤트가 오면 `stream()`을 다시 불러 401을 유도하고, `tellExpired`가 알림을 띄우는 구조였다. 화면 전환은 `(tabs)/_layout.tsx`의 `if (!c.demo && !(c.pairing && c.signedIn)) return <Redirect href="/" />;` 한 줄이 전부였다.

처음엔 리다이렉트 조건이 잘못됐다고 봤다. `signedIn`이 `demo || token !== undefined`로 계산되는데, 로그아웃 시점에 `token`이 안 지워지는 게 아닐까 의심했다. 그런데 `signedOutHere`를 다시 읽어 보니 `tokenNow.current`와 `setToken(undefined)`가 정확히 호출되고 있었다. 조건은 맞았다.

> Redirect는 그 화면 안에서만 동작한다. 스택 위에 쌓인 화면은 건드리지 않는다.

문제는 조건이 아니라 위치였다. Expo Router의 `Redirect`는 현재 라우트 세그먼트를 바꿀 뿐, 그 위에 쌓인 스택을 닫지 않는다. 세션·설정·문서 화면이 스택에 남아 있으면 탭 레이아웃이 리다이렉트돼도 뒤로가기가 그 화면으로 돌아간다. `settings.tsx`에 이미 `router.canDismiss()`와 `dismissAll()`을 쓰는 곳이 있었는데, 그걸 다른 화면에는 적용하지 않은 게 화근이었다.

해결은 로그인이 끝나는 순간 어느 화면에 있든 쌓인 화면을 모두 닫고 로그인 화면으로 바로 가게 만드는 것이었다. `_layout.tsx`, `(tabs)/_layout.tsx`, `settings.tsx` 세 파일을 고쳤다. 세 경로(시간 만료, PC에서 끊기, 직접 로그아웃)가 모두 같은 함수를 타게 통일했다. 페어링 해제는 지금처럼 처음 화면으로 가게 남겨 뒀다.

타입 검사는 통과했고 테스트 134개가 통과했다. 실제 폰에서는 아직 돌려 보지 않았다.

## 모바일 "세션 없음" PC — 폰에서 켤 방법이 없던 문제

폰 홈의 PC 목록에 VM 하나가 "세션 없음"으로 떠 있었다. PC에는 등록돼 있지만 자동 연결을 꺼둔 상태였다. 새로고침 버튼이 안 보여서 폰에서는 켤 방법이 없었다.

`home.tsx` 120~175줄과 i18n을 봤다. `pc_off: "세션 없음"`, `pc_failed: "연결 안 됨"`. 새로고침 버튼이 `pc_failed` 상태에서만 렌더링되는 조건이 걸려 있었다.

처음엔 PC 쪽 다시 연결 기능이 꺼둔 PC를 지원하지 않는 줄 알았다. 그래서 PC 코드부터 봤는데, 다시 연결은 "자동 연결 꺼 둠" 상태의 PC도 연결하고 있었다. PC 쪽은 이미 됐다.

> PC 쪽 다시 연결은 이미 꺼둔 PC를 지원했다. 막고 있던 건 폰의 버튼 노출 조건이었다.

| 상태 | 뜻 | 새로고침 버튼 |
|---|---|---|
| `pc_off` (세션 없음) | 등록됐지만 이번에 연결 시도 안 함 | 전: 없음 → 후: 있음 |
| `pc_failed` (연결 안 됨) | 시도했는데 실패 | 있음 |

`pc_off`는 "등록은 됐지만 이번에 연결 시도 안 함", `pc_failed`는 "시도했는데 실패"다. 새로고침 버튼은 후자에만 붙어 있었다. 그래서 꺼둔 PC는 폰에서 영영 켤 수 없었다.

`pc_off`에도 새로고침 버튼을 보이게 하고, 누르면 그 PC 하나만 연결을 시작하게 했다. 지난번에 열어 둔 패널이 있으면 그대로 다시 열고, 없으면 그 PC의 터미널만 열어서 연결한다. AI는 저절로 켜지지 않고, PC 화면에 AI 선택 창도 뜨지 않게 PC 쪽도 같이 고쳤다. 다른 PC는 건드리지 않고, 같은 PC는 10초에 한 번만 누를 수 있게 제한을 걸었다.

타입 검사는 통과했다. 실제 폰과 VM으로는 아직 확인하지 못했다. 폰 앱과 PC 앱을 둘 다 새로 빌드해야 확인할 수 있다.

## worktree 설계 — "규칙으로 충돌 막기"에서 "worktree = 폴더 하나"로

한 프로젝트에서 AI 여럿을 동시에 돌리고 싶었다. 지금 Lepons는 프로젝트(PC+폴더)당 AI 하나다.

처음엔 규칙만 정해서 한 폴더에서 같이 돌리면 될 거라 봤다. "이 파일은 네가, 저 파일은 네가" 하고 규칙으로 정하면 되지 않을까 했다.

조사해 보니 안 됐다. 두 AI가 같은 폴더에서 동시에 커밋하면 `.git/index.lock`이 충돌한다. 한 AI가 `git add -A`를 하면 다른 AI가 쓰다 만 파일까지 커밋에 섞인다. 한 AI가 브랜치를 바꾸면 다른 AI의 파일도 전부 바뀐다. 같은 파일을 둘이 고치면 나중에 저장한 쪽만 남는다.

> 규칙으로는 못 막는다. 폴더 자체를 나눠야 한다.

git worktree로 방향을 잡았다. git 기록은 같이 쓰고 작업 파일만 다른 폴더에 펼쳐 두는 방식이라, 몇 초면 만들어지고 용량도 작다.

그다음엔 사용자에게 "같은 폴더에서 같이 작업 / 따로 작업하고 나중에 합치기" 선택지를 물어보려 했다. 그런데 코드를 읽어 보니 PC 앱은 한 프로젝트에 AI를 하나만 띄울 수 있었다. 같은 폴더에 AI를 하나 더 열면 기존 AI가 닫히고 새것으로 바뀐다(`openOrRestart`). 그래서 "같은 폴더에서 같이 작업"이라는 경우는 애초에 없었다. 선택지 자체가 불필요했다.

결정은 worktree 하나를 그 PC의 폴더 하나로 등록하는 것이었다. 그러면 상태 표시, 지난 대화, 재시작 후 복원, 폰 목록, 작업 맡기기가 지금 코드 그대로 동작한다. 새로 만들 건 git 명령, 패널 버튼 네 개, 사이드 패널 줄, 워크플로우 갈래 정도로 줄었다.

설계 문서는 `docs/superpowers/specs/2026-11-08-worktree-design.md`에 정리했다. 실제 git으로 돌리는 테스트 10개를 포함해 PC 테스트 964개가 통과했다. Electron 앱 실행, SSH 원격 PC, 폰 기기에서는 아직 확인하지 못했다. Claude가 다른 폴더에서 만든 대화를 바로 이어받지 못하는 문제는 대화 기록 파일을 worktree 쪽으로 복사해서 넘기게 만들었는데, 이것도 실제로 돌려 보지 않았다.

## worktree 지우기 — 확인 없이 강제 삭제되던 문제

worktree를 지울 때, git이 남은 작업을 확인하지 못하면 확인 창 없이 강제로 지우고 있었다. 반영 안 한 작업이 말없이 사라질 수 있는 경로였다.

`worktree.test.ts`와 `removeWorktree` 쪽을 다시 읽었다. `pendingWork`가 남은 작업을 확인하는 함수인데, 실패하면 `undefined`를 반환하고 호출부가 그걸 "남은 작업 없음"으로 해석하고 있었다.

> `undefined`(확인 못 함)와 `[]`(남은 작업 없음)를 같은 값으로 취급하고 있었다.

처음엔 "git이 확인 못 하는 경우는 드물다"고 넘길 뻔했다. 그런데 드문 것과 안전한 것은 다르다. 실패가 조용히 성공처럼 흘러가는 코드는 언젠가 한 번 크게 물린다.

`pendingWork`가 `undefined`일 때도 "남은 작업을 확인하지 못했어요. 그래도 지울까요?" 확인 창을 띄우게 고쳤다. 실패를 성공으로 취급하지 않게 만드는 게 핵심이었다.

같이 잡은 것 두 가지가 더 있다.

- **앱 켤 때 worktree가 목록에서 빠짐:** `goneWorktrees`가 경로 문자열만 비교해서, 표기가 git과 다르면 사라진 것으로 판단했다. 이제 그 폴더가 실제 git 작업 폴더로 응답하면 목록에 남긴다. 이 경우를 확인하는 테스트도 추가했다.
- **bypass permissions 설정이 꺼짐:** 앱을 켠 직후 선택 창을 거치지 않고 다시 연결하면 저장해 둔 설정이 꺼지고 덮어써졌다. 시작할 때부터 저장된 값으로 맞추게 고쳤다.

worktree 테스트 10개가 통과했고, 전체 PC 테스트 964개(실패 0)와 모바일 136개가 통과했다. 타입 검사 3종도 통과했다. 다만 Electron 앱 실제 실행과 폰 기기 확인은 여전히 남아 있다.

### 오늘의 한줄

실패와 성공을 같은 값으로 취급하는 코드가 가장 위험하다. `undefined`와 `[]`, `pc_off`와 `pc_failed`, 쌓인 화면과 빈 화면을 구분하지 않은 자리에서 버그가 나왔다.
