오늘은 자동 지원 파이프라인과 라피드, 레폰즈 세 갈래에서 각각 다른 종류의 문제를 잡았다. 자동 지원은 네 번 연속 자격 미달로 멈춰서 수집 기준 자체를 의심해야 했고, Vercel 이전은 배포는 됐는데 로그인 창이 안 뜨는 상태에서 환경변수 적용 시점을 놓치고 있었다. 라피드는 외부 API 스펙이 조용히 바뀌어 룩 연구소가 전부 실패했고, 레폰즈는 원격 서버 사용량이 0으로 보이는 게 집계 명령이 실패해도 성공처럼 보이는 구조 때문이었다.

## 자동 지원 4건 연속 차단 — 수집 기준이 실제 경력과 안 맞았다

자동 지원 버튼을 붙여 두고 실제 공고로 돌린 첫 네 건이 전부 제출 전에 멈췄다. 삼성메디슨 SW개발, LG에너지솔루션 AI/빅데이터, 지원 회사 이츠 카탈로그 분석, 카카오모빌리티 서버 개발자 순서였다. 앞의 세 건은 자격 미달, 마지막 한 건만 제출 버튼 앞까지 갔다.

처음엔 공고마다 조건이 달라서 그런 줄 알았다. 삼성메디슨은 OPIc IL이나 토익스피킹 110점 이상이 필수였고 원장의 `english_test`는 비어 있었다. LG에너지솔루션은 신입에 석사 졸업(예정)자만 받고 학사는 경력 만 36개월 이상을 요구했는데 원장상 경력은 2026년 2월부터라 10개월이 안 됐다. 지원 회사은 필수 동의 6번이 평판조회였고 공고 연봉이 3,600만 원이라 성과급 100%를 더해도 3,900만 원으로 4,500만 원 기준에 못 미쳤다.

> 세 건이 각자 다른 이유로 막혔지만, 원인을 하나로 모으면 "수집 기준이 실제 내 경력과 안 맞는다"였다.

캘린더 수집 지시문에는 "경력 3년 이하"가 들어가 있었다. 원장 기준 경력이 10개월인데 3년 이하를 다 담으면, 실제로는 지원할 수 없는 공고가 계속 쌓인다. 남아 있던 상시 공고 47건을 Aside로 하나씩 열어 자격을 다시 확인했더니 **40건이 빠졌다**. 토스 계열 30건 전부가 전형에 레퍼런스 체크를 넣고 있었고, 라인 4건, CJ ENM, 크래프톤도 같은 이유였다. 라인 1건은 경력 3년 이상, 삼성메디슨은 영어 성적, 지원 회사로지스틱스 1건은 지원서 필수 동의가 평판조회였다.

해법은 두 군데를 바꾸는 것이었다. 수집 지시문의 경력 조건을 "2년 이하"로 좁히고, 공고별 상세 페이지에서 자격을 직접 확인해 요구 경력 2년 초과·석사 이상 필수·평판조회·영어 말하기 성적 필수·근무지 불일치·인턴 중 하나라도 걸리면 넣지 않게 했다. 자격을 확인하지 못한 공고도 넣지 않는다. 빠진 공고는 이유와 함께 삭제 표시로 남겨서 다음 수집이 되살리지 않게 했다.

검증은 카카오모빌리티로 했다. 판교, 계약직 6개월, 경력 무관, 인턴 아님, 대기업 계열, 2년차 연봉 4,707만 원(잡플래닛)으로 모든 필터를 통과했다. 10분 만에 지원서를 다 채우고 제출 버튼 앞에서 멈췄다. 이 사이트는 임시저장이 없어서 Aside 탭을 닫으면 처음부터 다시 채워야 한다는 것도 이때 알았다.

## Vercel 배포 후 로그인 창 대신 에러 — 환경변수는 등록됐는데 재배포를 안 했다

캘린더를 로컬 8802에서 Vercel로 옮기고 나서, 배포는 성공했는데 접속하니 로그인 창 대신 `{"error":"서버 환경변수가 설정되지 않았습니다"}`가 떴다. 처음엔 Upstash Redis 연결이 안 된 줄 알았다.

`vercel env ls`로 확인하니 `APP_PASSWORD`가 43초 전에 등록돼 있었다. `SESSION_SECRET`은 48분 전에. 값은 있는데 서버가 못 읽는다는 뜻이었다.

> 원인은 환경변수가 아니라 타이밍이었다. 환경변수는 등록한 뒤 **재배포해야** 그 빌드에 적용된다.

그 전에 이미 한 번 우회로를 돌아가 있었다. Upstash를 CLI로 붙이려고 `vercel integration add upstash`를 실행했더니 "Product not found"로 실패했다. 자동으로 답을 넣는 스크립트를 짜서 다시 돌렸더니 CLI가 "약관 동의를 위해 대시보드를 여시겠습니까?"를 물었고, 스크립트가 같은 질문에 "y"를 여러 번 보내서 대시보드 탭이 여러 개 떴다. 확인 없이 브라우저를 여는 방식으로 짠 내 실수였다. 그때 실제로 바뀐 건 `apply-calendar` 프로젝트 생성과 세션 서명 키 등록 두 가지뿐이고, 결제나 저장소 생성은 일어나지 않았다.

재배포하고 나서 Playwright로 실제 주소를 열어 확인했다. 로그인 전에는 서버가 정상적으로 `{"error":"login"}`을 돌려주고, 페이지에는 "지원 캘린더 / 비밀번호 / 들어가기"가 떴다. 90일 쿠키, 10번 틀리면 15분 잠금도 함께 붙였다. 검증 중에 내가 틀린 비밀번호를 한 번 넣었는데 그 실패 기록은 지워 두었다.

## 룩 연구소가 전부 실패 — NVIDIA API가 seed 파라미터를 거부했다

라피드의 룩 연구소 역추적을 3건 돌렸는데 3건 모두 `failed`로 끝났다. 로그에 찍힌 건 `NVIDIA 이미지 생성 실패 HTTP 422: {"detail":[{"type":"extra_forbidden","loc":["body","seed"],"msg":"Extra inputs are not permitted","input":0}]}`였다.

전에는 잘 돌던 코드였다. 무료 NVIDIA NIM으로 FLUX 이미지를 만들 때 `seed`를 함께 보내고 있었는데, API 스펙이 바뀌어서 그 파라미터를 더는 받지 않게 된 것이다. `generate_keyframe.py`에서 `seed`를 빼고 다시 돌렸더니 이미지 생성이 정상으로 돌아왔다. 실패로 표시된 두 후보는 다시 대기 상태로 되돌렸다.

같은 작업 중에 더 조용한 문제도 하나 나왔다. B등급 영상 모델을 `seedance-2.5-flash`로 교체하려고 OpenRouter 모델 목록을 뽑아 봤더니, 원래 B등급에 쓰던 `seedance-1-5-pro`가 목록에 아예 없었다. 그대로 두었으면 B등급 유료 제작이 다음 실행에서 실패했을 것이다.

여기서 한 번 더 꼬였다. C등급 대체 모델도 같이 2.5 Flash로 바꿨는데, Flash는 2.5의 빠르고 싼 하위판이라 C등급을 오히려 깎은 셈이었다. 바로잡아서 C는 `bytedance/seedance-2.5` 정식판(720p, 초당 $0.231)으로, B는 2.5 Flash 480p로 분리했다. "C는 B와 다른 모델을 쓴다"를 확인하는 테스트도 추가했다.

## 원격 서버 사용량이 0으로 보임 — 서버 셸 경고가 기록 줄을 삼켰다

레폰즈 사용량 화면이 이 PC 기록만 읽고 있었다. 원격 서버에서 돌린 AI 사용량은 그 서버 안에 남으니까 화면에 안 잡히는 게 당연했다. 등록된 원격 PC마다 SSH로 집계 명령을 한 번 돌려서 토큰 숫자·모델·시간·폴더 경로만 받아오는 방식으로 바꿨다. 대화 내용은 가져오지 않는다.

첫 구현은 서버 셸이 띄우는 경고 메시지에 취약했다. 경고가 기록 줄 중간에 끼면 그 파일이 통째로 빠졌다. awk가 없거나 명령이 중간에 끊겨도 사용량이 0인 것처럼 보였다. 경로가 너무 길어 임시 파일 하나를 못 쓰면 그 서버 사용량이 전부 빠졌다. 같은 주소로 여러 번 등록된 PC는 폴더 이름이 합쳐지지 않았다.

> 집계 명령이 실패해도 결과가 "0"으로 나오는 구조가 가장 위험했다. 실패와 진짜 0을 구분할 방법이 없었다.

네 가지를 고쳤다. 명령이 끝까지 돌았을 때만 마지막에 `LPEND` 표시를 남기고 그 표시가 없으면 "일부 기록을 읽지 못함"으로 처리한다. 서버 셸 경고는 stderr로 보내 처음부터 버린다. 임시 파일 하나가 실패하면 그 파일만 빼고 나머지는 센다. 같은 주소로 등록된 PC는 각 항목의 폴더 이름까지 합쳐서 쓴다.

검증은 이 PC의 실제 기록에 같은 명령을 돌려서 직접 센 값과 서버 방식으로 센 값을 비교했다. Codex는 정확히 같았고, Claude는 0.05% 정도 덜 셌다. 어느 줄이 빠지는지 추적해서 고쳤다. 실제 원격 서버에서는 아직 안 돌려 봤기 때문에, 리눅스와 맥의 기본 awk 차이는 다음 확인 때 봐야 한다.

### 오늘의 한줄

자동화에서 가장 위험한 실패는 에러로 멈추는 게 아니라 성공처럼 보이는 실패다 — 오늘 잡은 네 건 중 세 건이 그랬다.
